# 点数据真实节点与时间对齐修复

本批修复所有复用公共点读取器的交通模型，不增加模型迁移计数。问题在 HIEST 的物理节点重排检查中发现，因此先独立交付，HIEST 原生迁移另行继续。

## 原问题

旧 `_load_dyna_3d` 从文件最前面若干行推断时间轴，再按固定行块重塑为「节点×时间」。它要求 `.geo` 与 `.dyna` 节点顺序恰好一致，也要求同节点的时间行连续。真实 ID 虽然存在于 entity_id，却没有用于填充数组；乱序/时间优先存储或 `.geo` 重排时，邻接矩阵按 geo_id 排列，观测仍按文件行块排列，会静默错配。

重复、缺失或未知节点记录还可能被当成普通值重塑。即使修正读取器，原始缓存仍可能保存旧位置语义的错误数组；原先公共点元数据也没有明确记录实际节点 ID 顺序。

## 修复方式

读取 `.geo` 顺序定义张量节点轴；要求节点 ID 非空、有限、唯一。`.dyna` 用 entity_id 映射真实 geo_id，用带 UTC 的时间解析生成排序后的唯一时间轴。逐行计算「时间位置、节点位置」，一次填入 `[T,N,F]`；不按 CSV 的行块或 dyna_id 大小猜测位置。

要求每个时间×节点恰有一行。拒绝重复/缺失记录、未知 ID、无效时钟、无限值、空数据和非法观测列。实际缺测仍可显式写 NaN，不把缺测目标改成 0；日期偏移统一为 UTC。原本已正确按 geo 顺序存储的数据保持相同数值和样本定义。

元数据增加只读 node_ids 和 point_alignment=timestamp_entity_id_v2；缓存冷/热读取保持同一身份说明。原子缓存使用新的 point-time-entity-v2 命名空间，保留旧文件，不复用旧位置语义数组。目录仍在独立 cache_dir 下；只对配置命名，不哈希源文件内容，来源版本仍使用路径/大小/修改时间。

## 检查点影响

点数据输入身份发生明确版本切换。完整续训和独立评估会通过公共输入说明/数据状态检查拒绝缺少新 node_ids/对齐声明的旧检查点；不会自动给旧权重补声明，也不会改写旧文件。请在新语义下重新训练，避免把已按错误节点绑定训练的权重伪装为已修复。原始 CSV 仅重新排列行而实际身份、数值和时钟不变时，独立评估仍允许；改变真实节点轴顺序则明确拒绝静默加载旧权重。

此版本标记针对公共点输入，不把轨迹、ETA、地图匹配、道路表征或独立原生网格/OD 适配笼统判为同一变更。

## 验证

新增 18 项：数字/文本非连续 ID、节点分块/时间优先/完全乱序 6 组；逐原始时间和真实 ID 复算所有观测/目标/图，验证冷热缓存身份一致；9 类无效节点/完整性/时钟/数值输入拒绝；模拟旧位置缓存不复用且旧文件保留；UTC 偏移与原始 NaN 保留；真实训练后 CSV 行重排评估一致，而缺失新身份声明或改变 geo 顺序时权重加载拒绝。相关缓存、切分和配置检查合计 43 项通过。

完整回归 1281 项通过、无失败/错误/跳过，见 [汇总](remaining-validation.json)。公开 GRU 的仓库外夹具生成、训练、独立评估和续训 4 条命令均成功，IDs [108,71,3]、完全打乱观测行，导出真值按原始时间/真实 ID 逐项一致；预测 [9,2,3,1]，独立预测/指标一致，第三轮累计 9 次更新，纯权重包含新对齐声明、独立评估无训练产物，见 [CLI](point-identity-cli-validation.json)。该公开配置 cache=false，CLI 三次均 disabled；缓存命中/旧缓存隔离由专项验证。本批不扩展模型支持范围，不代表所有延期 Dataset 及其旧布局均已重写。
